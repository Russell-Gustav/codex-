# Codex 思考日志监视器

这个版本采用旁路常驻监听架构。点击“开始监听”后，监视器通过 Windows 原生目录变更通知跟踪 Codex Desktop 写入 `$CODEX_HOME/sessions` 的 `rollout-*.jsonl` 会话记录，同时保留周期扫描作为漏通知兜底；之后可以直接回到 Codex 创建任务和发送消息。新会话和已有对话中的后续 turn 都会被增量展示。它不会启动第二个 Codex，也不会修改 Codex 的状态数据库。

- 推理摘要（当 Codex CLI/模型公开时）；
- 工具调用和命令执行；
- Agent 输出；
- 生命周期、诊断和错误；
- 完整原始 JSON 事件。

它不会、也不能读取模型未公开的完整隐藏思维链。界面将“Codex原始事件”和“监视器推断的阶段”分开显示。

## 运行

直接使用根目录中的`CodexMonitor.exe`只要求Windows、Microsoft Edge，以及已安装并登录的Codex。只有修改源码、运行测试或重新构建时才需要Node.js 20或更高版本。

启动时会自动检索 Codex CLI 和数据目录。检索顺序包括 `CODEX_EXECUTABLE` / `CODEX_PATH`、系统 `PATH`、npm 全局目录、WinGet 链接及常见用户级安装目录；数据目录优先使用 `CODEX_HOME`，否则使用当前用户目录下的 `.codex`。检测结果会显示在监视器左侧，并记录到当前用户可写的数据目录：

```text
%LOCALAPPDATA%\CodexThoughtMonitor\runtime\codex-location.json
```

运行日志保存在 `%LOCALAPPDATA%\CodexThoughtMonitor\logs`。因此便携版可以放在只读目录中运行，也不会把其他电脑的 Codex 路径打进发布包。

如果没有找到 CLI 可执行文件，程序仍可使用会话文件进行只读旁路监听；只有主动创建和控制 Codex 会话的功能需要 CLI。

### 直接运行与构建

双击项目根目录中的`CodexMonitor.exe`即可打开模式选择界面。重新构建时运行：

```powershell
npm run build:portable
```

构建结果会直接覆盖根目录中的`CodexMonitor.exe`；`public`和`formal`目录是程序运行资源，需要与可执行文件保持在同一项目目录中。

### 网页模式

在 VS Code 中打开本目录，然后在集成终端运行：

```powershell
npm run web
```

服务启动后会自动在本机Microsoft Edge普通窗口中打开：

```text
http://127.0.0.1:4317
```

当前网页和轻量桌面模式都只使用Node.js标准库与系统已有的Microsoft Edge，不需要额外安装前端或桌面运行库。

如果不希望自动打开浏览器，只启动后台服务：

```powershell
npm run web:server
```

### 桌面模式

启动独立桌面窗口：

```powershell
npm run desktop
```

桌面模式使用Windows自带的Microsoft Edge应用窗口承载界面，不显示普通浏览器地址栏，不需要额外下载Electron。桌面端与网页端共用同一个Node服务、可视化页面、SSE事件流、AWDL检测器和JSONL日志。桌面窗口运行时，浏览器仍可访问`http://127.0.0.1:4317`，两端会同时收到后续事件。

## 分析视图

监视页将同一条实时事件流投影为六种用途不同的视图：

- **工作流图**：按发生顺序绘制状态节点。绿色表示成功结果或本轮完成，红色表示告警引用的证据；图上方说明当前是否触发规则。相似的状态序列不能单凭形状判为错误。
- **判错规则**：逐项说明当前 AWDL 的触发条件、阈值、是否命中，以及相关证据事件编号。
- **逻辑层**：展示“原始事件 → 分类器 → 状态迁移 → 进展判定”的处理结果，区分动作、观察、输出与异常是否构成可验证进展。
- **AWDL分析**：直接展示当前AWDL版本、状态/终态、检测阈值、合法迁移关系，以及每条告警对应的规则和证据事件编号。
- **通信流**：把事件按监视器/AWDL、Codex、工具/命令和用户输出划分为泳道，展示信息在不同参与方之间的流向。
- **原始事件**：保留逐条事件、正文和原始JSON，用于审计与问题复现。

网页模式和程序模式使用相同的分析能力与数据接口，但采用不同窗口：网页模式打开普通Edge浏览器窗口；程序模式打开隐藏地址栏和标签页的独立应用窗口。选择完成后启动中心会自动关闭。

## 4.0 真实 Agent 协同演练

选择一个已监听到的 Codex 会话后，可以启动“规划活锁”或“重复重试”演练。监视器先通过 Windows UI Automation 读取 Codex Desktop 当前可见文档的对话标题和忙闲状态，再通过 app-server 的只读 `thread/list` 将标题唯一映射到 threadId；只有它与监视器所选会话完全一致时，才把带唯一 `AWDL-SIM-*` 标记的一次性协议直接提交到当前可见输入框。发送后还必须在同一原会话的 rollout 事件中观察到该标记和新 turn，才进入检测流程。窗口、标题或会话存在歧义时会拒绝发送，避免误投到其他对话。

演练触发 AWDL 告警后，监视界面会显示“继续观察/终止 Agent”确认框。选择终止会对当前可见会话执行停止操作，并在事件流中记录中断请求和最终状态。演练完成、失败或中断后，界面恢复两个演练按钮并关闭过期的告警确认框。

左侧“开始监听”只建立只读文件增量监听；启动时从已有文件末尾开始，因此不会把全部历史记录灌入页面。之后新增的会话、turn、用户消息、Codex 回复、公开推理阶段和工具事件会自动进入 SSE 与 AWDL 分析。左侧“形式化检测验证”仍提供两条确定性测试轨迹，用于单独验证 AWDL 告警展示。

旁路监听不会控制或中断 Codex Desktop 中的任务；它只负责稳定观察和表述状态。停止监听只关闭文件观察器，不会影响 Codex。关闭整个监视器时会先释放监听器，再关闭 HTTP/SSE 连接。

## 数据

程序不会依赖开发者机器上的固定绝对路径。每次启动都会重新检测 Codex 位置并覆盖位置记录，以适应安装目录、用户账户或便携环境的变化。

每次演练产生的运行日志都会保存到：

```text
%LOCALAPPDATA%\CodexThoughtMonitor\logs\run-<timestamp>.jsonl
```

每条记录包含统一时间戳、事件类别、推断阶段、可读内容、数据来源和 Codex 原始事件。

## AWDL形式化检测

默认工作流规范位于`formal/default-workflow.awdl.json`，语言定义和故障特征见`docs/AWDL.md`。实时事件会进入AWDL检测器，触发后在页面显示独立告警卡。

离线分析已有日志：

```powershell
npm run analyze -- "%LOCALAPPDATA%\CodexThoughtMonitor\logs\run-<timestamp>.jsonl"
```

当前检测：非法迁移、事件预算超限、连续错误、重复动作、无进展窗口、周期活锁、规划空转和静默停滞。

## 当前边界

- 原生目录通知通常会立即触发扫描，另有约 2 秒周期兜底；
- 监听覆盖启动监听后所有 Codex Desktop 会话，不限于当前项目目录；
- 只展示 Codex 已写入会话记录的公开事件，不能读取隐藏思维链；
- 推理摘要是否出现取决于当前 Codex 版本、模型和账户配置；
- 监听器会过滤系统/开发者提示、world state、token usage 和加密推理内容，并限制单条展示长度；
- 增量读取使用字节级换行解析，能处理 UTF-8 分片、不带尾换行的完整事件、文件截断、替换和同尺寸重写；
- 该方案依赖 Codex 当前的本地会话记录格式。格式变化时需要更新 `detector/session-watcher.js` 的映射。
